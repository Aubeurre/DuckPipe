Ducky Node Manager

Ducky Node Manager permet aux artistes de gérer efficacement tous les éléments d’une production 3D, depuis une interface simple et centralisée.
Il offre un accès rapide à la structure du projet, permet de créer des assets, séquences et plans, de versionner les fichiers de travail, de publier des livrables et de verrouiller les fichiers pour éviter les conflits de modification.
Tout est conçu pour fluidifier le pipeline de production et automatiser les tâches répétitives en assurant la securitee des fichiers.



Installation

Pour une instalation rapide de l'asset manager Ducky, suivez la page Install Ducky Node Manager.


Gestion d'une production

Creation des productions

DuckPipe permet la creation de production 100% personnalisée, en fonction des besoins du studio.
Lors de la création d’une nouvelle production, une arborescence standardisée est générée automatiquement, incluant les dossiers pour les assets, séquences, plans, et autres éléments nécessaires.
C'est vous qui décidez de la structure de vos dossiers, des départements impliqués dans chaque assets, ainsi que le ou les logiciels utilisé pour chaque departements.

Configuration des productions : config.json

DuckPipe s’appuie sur un fichier config.json pour définir règles spécifiques au projet.
Chaque production dispose de son propre fichier de configuration, cree automatiquement lors de la création de la production.
Modifier ce fichier permet d’adapter le pipeline aux besoins spécifiques d’un projet sans toucher au code source
Vous pouvez definir les utilisateurs qui accedent a la productionm la customisation des couleurs de chaque departements, les status disponibles, ainsi que la date de debut et fin de production.

Structure et hierarchie : NodeStructure.json

Le fichier NodeStructure.json définit la structure par défaut des dossiers et fichiers pour chaque type d’asset (ex: Props, Characters, Sequences, Shots).
Il indique les départements impliqués, les chemins à créer, ainsi que les modèles de noms de fichiers.
Lors de la création d’un nouveau node, cette structure est utilisée pour générer automatiquement l’arborescence correspondante.

Il est donc possible d'editer le fichier afin de constituer une arboressence unique pour chaque production.

Gestion des Users

DuckPipe intègre une gestion des utilisateurs pour contrôler l’accès aux productions et aux fonctionnalités.

La gestion des noms d'utilisateurs se fait via le fichier user_config.json situé dans le dossier utilisateur de chaque machine.
Ce fichier est généré automatiquement à la première ouverture de DuckPipe, et peut être édité directement dans l'interface du tool.

Chaque production peut definir les utilisateurs qui font partie de la production, et ainsi restreindre l'accès aux personnes autorisées uniquement.
Les utilisateurs assignes a la production se retrouveront dans les listes droulantes d''assignation des taches, et dans les historiques de modification.



UI de DuckPipe

Overview

L'UI se decoupe en 2 parties principales : la barre latérale de navigation (a gauche), et le panneau principal de gestion.
La barre latérale permet de naviguer a travers les fichiers de chaque production. mais aussi de creer production ou node.
Le panneau principal affiche les détails de l'élément sélectionné, Il permet d'agire sur le node.
Il peut se decomposer en 4 sections :

  • Node (detail sur les assignation, les due date, et statue de chaque departement)
  • Work (action sur les scene de travial)
  • Shedule (Planing de la production)
  • Stats (Time logs et statistiques de la production)



Gestion d'un Node et travail

Creation : Node.json

A la creation d'un nouveau node, un fichier Node.json est généré automatiquement dans le dossier racine du node.
Ce fichier contient les informations de suivi du node, comme les versions de fichiers de travail, les publications, les statuts des departements, et les utilisateurs assignés.
le node est inscrit dans le fichier allNodes.json de la production.

Action sur le Node

Depuis le panneau principal, il est possible d'agir sur le node de plusieurs façons :

Onglet Node

  • Changer le statut d'un ou plusieurs departements
  • Gerer les start et due Date
  • Gerer les Assignation

Onglet Work
  • Grab / Ungrab (permet de lock un asset et eviter les conflits)
  • Exec (permet de creer ou recreer la scene dans son etat de base, avec template et references)
  • Run (Lance le work selectionne)
  • Increment (copie le local sur le serveur, et enregistre une versiondans les incrementals
  • Publish (fait une incremental, lance les scripts de publish, puis genere un "_OK" dans "dlv" .
  • Edit Ref (Permet d'ajouter ou suprimer les references a importer dans la scene (pour maya et blender)
Toutes ces actions mettent à jour le fichier Node.json pour refléter l'état actuel du node (n'oubliez pas le bouton "Save").

Grab / Ungrab

Le bouton "Grab" permet de verrouiller un asset pour éviter les conflits de modification entre plusieurs utilisateurs.
Lorsqu'un utilisateur clique sur "Grab", plusieurs actions sont effectuées automatiquement :

  • Le fichier work est copie du serveur vers le dossier local de l'utilisateur. (ON NE TRAVAIL PAS DIRECTEMENT SUR LE SERVEUR)
  • un fichier .lock est cree a la racine de la scene ed travail pour indiquer que l'asset est verrouillé par cet utilisateur.
  • Le nom de l'utilisateur est affiché dans l'interface pour informer les autres utilisateurs que l'asset est en cours d'édition.
  • Les autres utilisateurs ne peuvent pas modifier ou publier cet asset tant qu'il est verrouillé.
Pour libérer l'asset, l'utilisateur peut cliquer sur "Ungrab", ce qui deletera le fichier .lock et permettra aux autres utilisateurs d'accéder à nouveau à l'asset.
L'asset en local est suprimé, et il faudra refaire un "Grab" pour travailler a nouveau dessus.
Toute modification effectuée en local doit être sauvegardée sur le serveur via le bouton "Increment" avant de faire un "Ungrab".
Cela garantit que les modifications sont effectuées de manière ordonnée et évite les conflits de version.

Exec

Le bouton "Exec" permet de créer ou recréer la scène de travail dans son état de base.
Lorsqu'un utilisateur clique sur "Exec", plusieurs actions sont effectuées automatiquement :

  • Le dossier de travail local est créé s'il n'existe pas déjà.
  • Les références définies dans le fichier Node.json sont importées dans la scène.
  • Le template spécifique au type de node et au département est chargé si disponible.
Si une scène de travail existe déjà, elle sera remplacée par la nouvelle version générée par "Exec".
Cela garantit que l'utilisateur travaille toujours avec une scène propre et à jour, conforme aux standards du studio.

Template

Pour chaque Type de node et chaque departements, il est possible de definir un template de scene de travail.
Par exemple, pour le departement Model d'un Props, on peut definir un template qui portera le nom Props_Model_template.{ext}
Lors de l'exec de la scene de travail, le template prendra la place de la scene de travail.
Si aucun template n'est defini, une scene vierge sera ouverte.
Attention, le template doit se trouver dans un dossier specifique de la production

  • ..\ProdName\Assets\Template, pour les templates des Assets
  • ..\ProdName\Shots\Template, pour les templates des Shots et Sequences

Publish

Le publish permet de valider et de partager les travaux réalisés.
Lorsqu'un utilisateur clique sur le bouton "Publish", plusieurs actions sont effectuées automatiquement :

  • Une sauvegarde incrémentale est créée dans le dossier "incrementals" du département concerné.
  • Les scripts de publication spécifiques au département sont exécutés (par exemple, l'exportation de fichiers, la génération de playblasts, etc.).
  • Un fichier "_OK" est généré dans le dossier "dlv" pour indiquer que le travail a été publié avec succès.
  • Le fichier Node.json est mis à jour pour refléter la nouvelle version publiée et les changements de statut.
Les scripts de publication sont définis dans le dossier ..\MixedProd\Dev\Pythons de la production.
Ils peuvent être cree et personnalisés pour chaque département.
Par exemple, un script de publication pour le département "Rig" d'un "Characters" portera le nom Characters_Rig_publish.py.

Edit References

Le bouton "Edit Ref" permet de gérer les références à importer dans la scène de travail.
Lorsqu'un utilisateur clique sur "Edit Ref", une fenêtre s'ouvre pour permettre d'ajouter ou de supprimer des références.
Les références peuvent être des assets existants dans la production, tels que des personnages, des décors ou des accessoires.
Une fois les modifications effectuées, le fichier Node.json est mis à jour pour refléter les nouvelles références.
Lors du prochain "Exec", les références définies seront automatiquement importées dans la scène de travail.
Certaines scenes ont deja des references par defaut, qui seront importées a chaque exec. tel que la camera, pour les layout par exemple.

TimeLog

DuckPipe intègre un système de suivi du temps de travail pour chaque utilisateur sur chaque node.
L'utilisateur peut (et doit) enregistrer son temps de travail dans l'onglet "stats", bouton "Add Timelog"
Le panneau "Stats" dans l'interface principale affiche un résumé des temps de travail pour chaque département, permettant a la prod de suivre la progression et d'analyser la charge de travail.
Cela aide à identifier les goulets d'étranglement dans le pipeline et à optimiser la répartition des tâches.
